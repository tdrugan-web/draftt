# Opportunity tree

An opportunity tree connects a desired outcome to the user needs that could move it, and only then to solution ideas. It is Draftt's lightweight take on the opportunity solution tree described by Teresa Torres in *Continuous Discovery Habits* (2021); read the book for the full method.

## Structure
1. **Outcome** at the top: one measurable change for the user or business. "Fewer missed appointments," not "launch reminders."
2. **Opportunities** under it: 2 to 4 needs, pains, or desires users have. Phrase them as the user would ("I forget appointments I booked weeks ago"), and tag each [E], [A], or [S].
3. **Solution ideas** under each opportunity: at most two at this stage. More belongs in ideation, not framing.

## Rules
- Every solution sits under an opportunity. A solution with no opportunity above it is a feature request, not a frame.
- Place the person's original idea in the tree and mark it. Showing it beside alternatives is the point.
- Opportunities shouldn't overlap. If two are the same need in different words, merge them.
- If you can't name a second opportunity, say so: the frame may be too narrow, which is worth knowing.

## Format
Use a nested list in the artifact so it pastes into any tool. On the web surface the same list renders as a tree.
