# How-might-we questions

How-might-we (HMW) questions turn a problem into prompts for ideas. The method comes from design thinking practice popularized by IDEO and the Stanford d.school; this guide is Draftt's own summary.

## Good HMW questions
- Start from a real pain or need in the problem frame, not from the solution the person already has in mind.
- Leave room for more than one answer. "How might we send SMS reminders" has one answer; "How might we make it easy for patients to keep or change an appointment" has many.
- Stay specific to the user and situation.

## Three altitudes
| Altitude | Feels like | Example (fictional clinic) |
|----------|------------|----------------------------|
| Broad | Could reframe the business | How might we make missed appointments rare? |
| Mid | Points at a need, open to many ideas | How might we make rescheduling easier than not showing up? |
| Narrow | Close to a feature, still open | How might we confirm tomorrow's appointments without a phone call? |

Most HMW questions in a frame should be mid-level. Include one broad and one narrow so the team can see the range.

## Fixes for weak HMW questions
| Problem | Fix |
|---------|-----|
| Contains the solution ("...with an app") | Remove the solution and name the need |
| Too vague ("...improve the experience") | Name the user, the moment, and the pain |
| A yes/no question in disguise | Rewrite so it asks "how", with many possible answers |
| Repeats the problem statement | Split it into the specific needs behind it |
